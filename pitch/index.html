# pizzaclaim

The LLM never decides, approves or pays.
It reads and writes.

Four teams got the same two agents, nine tools and fifteen tickets. Everyone can make the happy path work. We spent our time on the paths that are not happy: the wrong agent, two requests in one message, a withdrawn claim, a process that dies halfway through a payment.

# States

  
11 states. One table. No surprises.

  
StateMachine.transition() refuses any move that is not in the table.
    Terminal states never move again. Every state maps to exactly one of the six logged agent states.

# Mixed requests

  
"Pay my invoice and change my address."

  
Rule: one ticket handles one operation. Anything else is noted, not carried out,
    and the customer is told to send it separately.

  

    

      
Router picks one agent. It never closes the ticket.

      
Agent picks one category for the main operation (A) and lists the rest as short phrases in other_requests (B).

      
gather keeps only A's facts and adds a note: "Not handled, to be sent separately: …"

      
A takes the normal path: clarification, decision, approval if needed, execution. B has no effect on it.

      
Final message: whatever the outcome, UNHANDLED_NOTE is appended when other_requests is not empty.

    

    

      
reply.txt


request: "Reimburse invoice INV-2026-008 and please
          move me to my new address."

category:       reimbursement_request
other_requests: ["address change"]

✓ Your invoice has been reimbursed: €180.00.
! Not handled, to be sent separately:
  address change.

    

  







  
# Crash-safe

  
Kill it at any line. It still pays once.

  
Every write goes through a write-ahead ledger that is saved before the domain is called.
    A reply can arrive in a new process, days later. The ticket picks up exactly where it stopped.

  

    
[ fig. 4 — the write path, and what happens if the process dies ]

Crash after…On restart

        
step 1Nothing written. Run normally.

        
step 2 or 3create_claim is not idempotent → look it up by provider + invoice no + year before calling again.

        
step 4Entry is DONE → return the stored result. A successful write is never repeated.

      

    

  

  

    
FROZEN FACTS
A reply can only add.
Original facts are frozen. A clarification reply fills the gap; it cannot rewrite the invoice.

    
FROZEN PROPOSAL
Approved means exactly that.
On approval we execute the stored call. The model is never asked for the arguments again. Rejected: nothing happens, we explain.

  







  
# Edge cases

  
Beyond the happy path.

  
Each one is a test. Pure checks in app/checks: no I/O, no model, no flakiness.

  

    
MIXED
Do A and B
One operation is handled; the reply says explicitly that the rest was not.test_other_operation_is_named_in_reason_and_message

    
WITHDRAWAL
"Never mind, forget it"
The ticket ends as no_change, even if a reroute was pending.test_withdrawal_wins_over_a_reroute

    
PRESCRIPTION
Right patient, right service
The prescription must name the same patient and service as the invoice.

    
ROUTING
Wrong agent ≠ rejected
The router can never close a ticket. A wrong agent costs at most one handover.test_category_from_the_other_agents_list_is_handed_over

    
THRESHOLD
€1 500.00 exactly
Approval is on the final reimbursement, not the invoice amount. Exactly 1500 is paid without approval.

    
DUPLICATE
payment_failed is still a duplicate
Blocks claims that are paid, pending approval, registered or payment_failed.

    
SCOPE
Only your own policy
A write on any policy but the ticket's own never reaches the domain.test_write_on_another_policy_is_blocked

    
INJECTION
We never echo the request
Closing messages are fixed texts, so harmful or injected text is not repeated back.test_closing_category_gets_a_fixed_message_without_the_request_text

    
TIMEOUT
The customer never answers
A suspended ticket expires on event timestamps: deterministic and replayable.test_timeout_replaces_the_open_question

    
DATES
Invoice before service
Rejected as invalid input, as is any non-EUR invoice.

    
CORRECTIONS
Fix the field, not the facts
On a format error the model may change only the field named in the error. Max 3, then handover.

    
NOT INSURED
Close before any write
A patient not on the policy closes the ticket before anything is written.test_not_insured_closes_before_any_write
